- **Pi as a provider.** CodeDen can run sessions on the Pi coding agent through its RPC mode, using the user's own Pi login, settings and extensions. Pi has no permission system of its own, so every tool call is decided by CodeDen's permission level: approved on the spot, refused with the reason for the model, or shown as an approval card, with read-only sessions enforced the same way. CodeDen's own MCP tools are registered with the session, and Pi's model list, thinking levels, steering, Stop and "Compact now" work as they do on the other providers. Sessions keep their files in CodeDen's home, so `pi --resume` stays the user's own. A resumed Pi conversation shows its real context usage, a long command's output streams into its tool call as it runs, and CodeDen's side jobs (session titles, follow-up suggestions) run on Pi too.
- **Plan mode and forking on Pi.** Pi has no plan mode, so CodeDen supplies one: while planning, edits and writing commands are refused and the turn's message says so, and the first change the agent tries becomes the plan approval, whose card carries the agent's own plan. Approving starts the work; declining hands the agent your note. A Pi conversation can also be forked from the session's fork button, and CodeDen's title for the session becomes Pi's own session name.
- **A Pi extension's dialogs reach you.** When one of your own Pi extensions asks a question during a session (`select`, `confirm`, `input`, `editor`), CodeDen shows it as a question card and hands your answer back to the extension; its notifications appear as notices.
- **Pi's own files in the Agents screen.** "What's loaded" now covers a Pi session: the context files it reads (`AGENTS.md`, `AGENTS.override.md`, `CLAUDE.md`) and the skills it finds in your Pi agent folder and in the project's `.pi/skills` and `.agents/skills`. They show up in the composer's `/` menu too.
